# Design decisions

Record of choices where the SPEC is silent or where we pick among allowed options.
Update when a phase introduces a new default.

## P0 agreed defaults

| # | Decision | Choice | Notes |
|---|----------|--------|-------|
| 1 | UI approach | **HTMX + SSE** (not a SPA) | SPEC §3/§4 allows HTMX or minimal vanilla JS; SSE for live progress. |
| 2 | SQLite access | **stdlib `sqlite3` first** | SPEC allows sqlite3 or SQLAlchemy Core; defer SQLAlchemy unless needed. |
| 3 | Retries / backoff | **Custom tiny backoff** | SPEC allows tenacity or custom; revisit if tenacity is clearly needed. |
| 4 | Portal password env | **`PORTAL_OPERATOR_PASSWORD`** | Seeded portal login uses operator@acmecorp.test + this env var. |
| 5 | Repo SPEC filename | **`docs/SPEC.md`** (uppercase) | Matches layout in SPEC §5. |
| 6 | Purchase orders | **12 POs: PO-501…PO-512** | Seed summary says “10 POs”; invoice table maps one PO each through PO-512 — use 12. |
| 7 | Session-expiry fault | **default N=5** | `session_expiry` invalidates after N requests; env `SESSION_EXPIRY_N` (default 5). |

## Layout / tooling notes (P0)

- **Package directory renamed `operator/` → `ark_operator/`.** SPEC §5 asks for `operator/`, but that name shadows the Python stdlib `operator` module. Putting it on `sys.path` breaks the interpreter (`collections` imports `operator.eq`). CLI entry point remains `operator` via `[project.scripts]`. Same internal module tree as SPEC otherwise.
- Mypy strict applies to `ark_operator/` (SPEC: strict on `operator/`).
- `uv.lock` is committed for reproducible installs.

## P2–P10 defaults

| Topic | Choice |
|-------|--------|
| Process keys | File stem (`INV-1004`) not extracted invoice number — keeps duplicate INV-1004 distinct from INV-1001 in the run |
| Idempotency | Irreversible portal submits use stable keys; duplicate_submit_guard honored |
| Verifier session | Fresh `portal_api` client; agent never grades itself |
| FLAG_DUPLICATE verify | Pass if original portal row already exists (INV-1004 after INV-1001) |
| Untrusted delimiters | `<<<UNTRUSTED_DATA>>>` around PDF/web text; INV-1010 → SECURITY_FINDING |
| DesktopTool | STUB interface only (`ark_operator/tools/browser.py`) |
| LLM in CI | FakeLLM + PolicyEngine; AnthropicClient only when `ANTHROPIC_API_KEY` set |
| Learning | Episodic memory records fault recoveries; second run under same fault improves |
| UI | Three HTMX screens (Handoff / Work / Proof) + Details; SSE for live progress |
| `make demo` | Headless subset INV-1001, INV-1008, INV-1010 against running portal |
| Approval gating | **Pause before browser submit** when `REQUIRE_APPROVAL` and no human decision yet — portal write is irreversible clearance |
| Idempotency terminal flag | Process keys only marked `terminal` after a finished outcome; awaiting approval is not terminal so resume re-enters |
| Duplicate verify | Fail if portal has a row whose `attachment_name` matches the duplicate file (INV-1004.pdf) |
| Learning lever | Run1 without lessons uses label-first submit (fails under `ui_rename`); run2 uses stable ids from episodic lessons |
| Verifier independence | Fresh `PortalApiTool` session per verify/repair cycle (separate from executor browser context) |
| Prompts | Versioned `.md` under `ark_operator/llm/prompts/`; FakeLLM scripts remain CI path |
| Crash-resume eval | Scenario 12 sets `crash_after_invoices` then resumes from the same event store |
| Duplicate keys on resume | `PolicyEngine.remember_seen()` re-seeds from terminal idempotency cache (INV-1004 still flags) |
| LLM selection | `build_llm()` → AnthropicClient if `ANTHROPIC_API_KEY` else FakeLLM |
| Default model | `OPERATOR_MODEL=claude-haiku-5-5` (cost-efficient structured JSON; not Opus/Sonnet) |
| LLM temperature | `temperature=0` on Anthropic plan/understand structured calls (SPEC) |
| Files sandbox | `company_world/` only — never `Path.cwd()` (`.env` exposure) |
| UI run start | Background thread so Work screen + SSE are live while pipeline runs |
| COMPLETED outcome | Set only after independent verifier passes (provisional NEEDS_ATTENTION post-submit) |
| FSM ownership | `runtime/fsm.py` is the only legal transition table; pipeline/orchestrator must call it |
| Pure fold | `fold_run` → `RunSnapshot` rebuilds state, irreversible keys, duplicate seeds |
| Exactly-once writes | `IrreversibleLedger` — commit only after successful browser submit |
| Verifier isolation | Fresh Playwright context in a worker thread + fresh portal_api (no shared cookies) |
| Security center | `security/envelope.py` + `security/redact.py` — EventStore append always redacts |
| Coverage gate | `make test` enforces ≥88% on policy/fsm/recovery/idempotency/verify/events |
| FakeLLM boundary | Scripts understand/plan **structure** only; never policy, portal writes, or verify |
